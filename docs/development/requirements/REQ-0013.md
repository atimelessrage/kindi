# REQ-0013: A tandem's GPU owner frees the layers it does not run

- Status: active

## Requirement

In a dense CPU+GPU tandem split, the GPU side must allocate only what it runs: the weights of the
layers it owns, the K/V of the attention layers it owns, and its own scratch. A layer moved to the
CPU must reduce the GPU footprint by that layer's real cost, not only by its weights, and the
placement planner must estimate the owner's real allocation when it decides how many layers to move.

## Acceptance

- The plan engine can own an arbitrary layer subset (`TPEngine(layers=...)`): non-owned tensors are
  never loaded, non-owned K/V is never allocated, and non-owned layers' f32 norms are never read.
- The tandem selects the owner explicitly (`--tandem-gpu auto|plan|plain`, `KINDI_TANDEM_GPU`), with
  the plan engine as the default on a single card.
- The placement estimate takes the owner into account: whole-f32 upload, device embedding and fp16
  K/V for the plain engine; owned f32 slices, no device embedding and q8_0 K/V for the plan engine.
- A split stays token-exact under the plan owner, including the joint prompt cache.
- A checkpoint (or saved opening) written by one owner is never restored into the other: the joint
  fingerprint records the owner and its K/V mode.

## Evidence

- `kindi/tp.py`: `TPEngine.__init__(layers=, embed=, head=)`, `Shard._slices`/`_load`/`alloc_ctx`,
  the per-block plans and `begin`/`layer`/`flush`/`get_hidden`/`set_hidden`/`finish`.
- `kindi/tandem.py`: `_pick_owner`, `gpu_estimate(..., owner=)`, `pack_bytes` per-layer f32.
- `tests/test_tandem.py`: owner selection, owner-aware estimate, per-layer f32 accounting, and the
  plan-owner wiring with a fake backend.
- Measured on the 27B at 24,576 tokens: peak 6,004 MiB (plan owner) against 7,721 MiB (plain owner)
  at the same placement, and a 49,152-token request kept unreduced where the unsplit engine reduces
  it to 30,976 — `docs/benchmarks/2026-11-14-i7-8086k-rtx4060ti-plan-owner/RESULTS.md`.
