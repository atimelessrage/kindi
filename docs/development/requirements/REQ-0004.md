# REQ-0004: CPU inference is exact and ISA-safe

- Status: active

## Requirement

The CPU engine must produce the verified token sequence on supported x86-64 CPUs,
check the instruction set before building, select one of the explicit ISA tiers,
and choose a thread count that does not collapse at hyperthread barriers.

## Acceptance

- The engine requires AVX; it selects the best available of the five explicit tiers
  (AVX2/FMA/F16C, AVX2/F16C, AVX2/FMA, AVX2, AVX-only) and fails with an actionable
  message when neither the CPU nor the compiler can provide a tier.
- The native Windows build path works without a vcvars shell when clang and the LLVM
  installation are supplied.
- The 2B, 4B and 9B CPU paths pass verification on every forced tier; the default is
  one thread per physical core, not one per logical CPU. Native old-hardware
  verification remains an explicit gap.
- A bare `clang`/`gcc` that is not on `PATH` resolves to a standard LLVM install before
  the build is attempted, and the cache key names the compiler that will run.
- The 27B pack loads and verifies token-exact on the CPU engine (exactness only; the
  27B stays a GPU target for speed).
- The native CPU server answers non-streaming and streaming chat requests with zero GPU
  memory in use.

## Evidence

- `kindi/cpu.py`, `kindi/kcpu.c` and `tests/test_cpu_build.py` implement and guard the
  build; `tests/test_cpu_threads.py` covers topology and defaults.
- [`CPU-SUPPORT.md`](../../CPU-SUPPORT.md) records the verification and thread sweep.
- `tests/test_cpu_smoke.py` and the opt-in CPU exactness test cover a compiled library.
- 2026-11-24: `kindi verify` with `KINDI_DEVICE=cpu` on the 27B pack is **4/4 token-exact**
  (40/40 tokens per prompt, 3.7 tok/s, 340 s load with a library built from the current
  `kcpu.c`; the cached 2026-11-20 build gave the same 4/4 at 2.0 tok/s) on the i7-8086K, after
  `kindi.packcheck.check(level="full")` passed on all 10 pack files and a structural audit
  agreed with the manifest (851 tensors, byte ranges tiling every file). Recorded in
  [`CPU-SUPPORT.md`](../../CPU-SUPPORT.md) and the generated support matrix. The same day
  `_find_cc` began resolving an off-`PATH` LLVM install, with `tests/test_cpu_build.py`
  covering detection, the cache key and the real compile/load of every tier on this host.
