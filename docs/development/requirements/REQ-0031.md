# REQ-0031: Looped-transformer model family (SenseNova-Loop-9B, Inkling 2 Mini)

- Status: active
- Implementation: Q0 header inventory measured 2026-11-22; recognition, specific refusal, the
  logical execution plan, stored-block coverage and `kindi loop-info` landed; no loader, pack,
  catalog entry or support claim.
- Targets: `sensenova_loop` (SenseNova-Loop-9B) and `inkling2` (Inkling 2 Mini)

## Requirement

Kindi must support looped transformers as a family, not as two one-off loaders. Both published
models reuse a middle block of layers several times per token, and both store each reused weight
once. Their GGUF `block_count` is the **logical** (unrolled) count, while the tensor names cover
only the **stored** blocks. A loader that iterates `range(block_count)` asks for blocks that are
not in the file: SenseNova has no `blk.28`, Inkling has no `blk.18`.

The shared contract is therefore:

1. recognize the architecture and its measured stored/logical map (`kindi/looped.py`);
2. refuse a looped file specifically, naming the family and REQ-0031, instead of the generic
   "expected a qwen35 ..." error (landed);
3. expose the full logical execution plan and validate that the tensor index contains every
   stored block before a loader consumes the file (`execution_plan`, `layout`, `kindi loop-info`;
   landed);
4. only then add a converter and loader that execute the loop with the family's own block:
   SenseNova's two-stream mHC and 3:1 linear/full attention, Inkling's 128-expert top-8 MoE,
   hybrid local/global attention and loop routing tensors;
5. pin a reference command and verify token-exact output before any support claim.

The two models are not one architecture with two sizes. SenseNova is a dense hybrid-attention
decoder with a two-stream residual mixer; Inkling is a sparse MoE with learned loop queries and a
different block convention. Only the logical-to-stored mapping is shared.

## Why the map is not optional

Measured from the public Q4_K_M headers (2026-11-22, 32 MiB HTTP range request each, no weights
downloaded):

| | SenseNova-Loop-9B | Inkling 2 Mini |
|---|---|---|
| arch | `sensenova_loop` | `inkling2` |
| declared `block_count` | 57 | 48 |
| stored block indices | 0-27 and 52-56 (33) | 0-23 (24) |
| loop | 4-27 executed twice; 28-51 absent | 6-17 executed three times; 18-41 absent |
| post-loop stored at | 52-55, nextn at 56 | 18-23 |
| tensors in the GGUF | 490 | 734 |
| quant types in Q4_K_M | F32, Q4_K, Q6_K | F32, Q8_0, Q5_K, IQ4_XS, MXFP4-class |

The post-loop convention differs: SenseNova keeps the logical index (52) for the first block
after the replay, while Inkling restarts at the physical index (18). A single "subtract the loop
length" rule would be wrong for one of them. `kindi/looped.py` encodes each family's
`post_base` and is tested against both boundaries.

## Acceptance

- **L1 (done 2026-11-22): header inventory.** One public Q4_K_M GGUF per family read with an HTTP
  range request; architecture, block counts, loop/mHC/MoE/attention keys, tensor count, quant
  types, context and vocab recorded in
  [benchmarks/2026-11-22-looped-model-headers](../../benchmarks/2026-11-22-looped-model-headers/README.md).
  No weights downloaded, no output claimed.
- **L2 (open): pinned artifacts and reference.** Record the full-file SHA-256 and byte size of one
  text-only GGUF per family, and a greedy reference command with its exact binary revision.
  SenseNova needs the vendor `OpenSenseNova/llama.cpp` at `24ea7bb` (upstream issue #31571 is open
  as of 2026-11-22); Inkling's GGUF is distributed with mainline-support copies, so a pinned
  mainline `llama.cpp` build should be enough. Record the prompt, tokenizer revision, output token
  ids and the first divergent logit.
- **L3 (partial 2026-11-22): map consumers.** `kindi convert` recognizes both families and refuses
  them with the measured map (landed, CPU-tested). `kindi/looped.py` also exposes a pure
  `execution_plan(spec)` (logical layer, stored block, phase and pass) and a `layout(g)` that
  reports missing and unexpected stored blocks from the GGUF tensor index. `kindi loop-info`
  (with `FILE.gguf [--json]`) prints the plan and coverage without loading tensor data; a changed
  `block_count` gets a specific refusal instead of the generic architecture error. A real
  converter still must remap logical layers to stored tensors, and a loader still must reject a
  missing stored block at execution time rather than silently reusing the previous layer.
- **L4 (open): token-exact gate.** `kindi verify` 4/4 greedy-exact at 2K context, text-only,
  against L2 for each family. SenseNova must assert the mHC stream routing and the 3:1 attention
  pattern; Inkling must assert the three loop passes and the top-8 router. No vision, MTP, DSpark
  or speculative path in L4.
- **L5 (open): memory envelope.** Record requested versus actual context and sampled peak on the
  available card. SenseNova's vendor minimum is about 9-10 GiB at 64K; Inkling's smallest public
  GGUF is 7.8 GB and the Q4_K_M file is 16.6 GB, so an 8 GB card cannot hold the file at all.
  Inkling's first Kindi target is the host-RAM/expert lane, not a fit; a "runs on 8 GB" claim is
  false until a larger-than-VRAM path is measured.
- **L6 (open): speed.** Same host, pack and context: p50 prefill and decode, with the loop block
  fused and unfused. No number is adopted before it is measured.
- **T0 (parked): precision.** Ternary or 2-bit experiments stay behind L4/L5, compare KLD/PPL and
  task output against the official 4-bit baseline, and are opt-in. The loop reuses the same
  weights, so quantization error is applied on every pass; embeddings, attention and the
  mHC/loop routing stay higher precision.
- **Standing:** no model enters `catalog.py`, the installer or the generated support matrix, and
  no doc says "supported", until L4 passes on a recorded reference.

## Evidence

- Header method and the full key tables:
  [docs/benchmarks/2026-11-22-looped-model-headers](../../benchmarks/2026-11-22-looped-model-headers/README.md).
- Reproducible shape: `curl -sL -r 0-33554431 <resolve-url> -o header.gguf.part` followed by
  `kindi.gguf.GGUF(header.gguf.part)`; the metadata and tensor index live in the first 32 MiB.
- Model sources: [SenseNova-Loop-9B](https://huggingface.co/sensenova/SenseNova-Loop-9B),
  [its GGUF](https://huggingface.co/sensenova/SenseNova-Loop-9B-GGUF),
  [Inkling 2 Mini](https://huggingface.co/thinkingmachines/Inkling-2-Mini),
  [the Unsloth GGUF mirror](https://huggingface.co/unsloth/Inkling-2-Mini-GGUF).
- Code: `kindi/looped.py` (map, plan, coverage and refusal), `kindi/convert.py` (dispatch),
  `kindi/__main__.py` (`loop-info`) and `tests/test_looped.py` (boundaries, plan, coverage, changed
  block count and the command).
- Reproduce the shared map from a header or full GGUF with
  `python -m kindi loop-info FILE.gguf --json`. The command only reads the metadata and tensor
  index; it does not serve a model or establish worker-kernel support.

## Out of scope for the first gate

Vision and image preprocessing (both models are multimodal), MTP for SenseNova, the bundled
DSpark drafter for Inkling, tool-call formatting beyond the chat template, and any speed claim.
