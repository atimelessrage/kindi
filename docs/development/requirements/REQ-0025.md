# REQ-0025: `kindi verify` can run under speculation

- Status: proposed

## Requirement

Every speculation mode must be token-compared against the reference exactly like the plain engine.
`docs/MTP.md` states that "the output of every mode was the same as without speculation"; no gate
checks it, and `kindi verify` cannot: `spec_mode` is only ever set by the server's engine build, so
the engine `verify` constructs has speculation off.

`kindi verify` must accept a speculation mode (`KINDI_SPEC=ngram|draft2b|dspine|mtp|both` and the
mode's own variables) and report the mode it ran, with the same 4/4-style exactness verdict.

## Acceptance

- **A1 (done 2026-11-17): the mode is selected by the harness, and reported.** `kindi verify --spec
  <ngram|mtp|draft2b|both|dspine|auto|0>` sets `KINDI_SPEC` for the run (the mode's own variables,
  `KINDI_MTP_HEAD` / `KINDI_SPEC_PACK` / `KINDI_SPEC_DRAFT_HEAD`, stay as set) and the first line is
  always `speculation: ...`: `requested mtp, effective mtp, head kindi-mtp-2b-v1.npz sha256
  1b5c0c790a59`, or `off (KINDI_SPEC=0)`, or `unavailable (this engine has no spec_begin)` for a
  plain engine. `spec.spec_state()` computes it from `spec.effective_state()`, the same resolver
  `/health` uses. A mode run wraps each prompt in `spec_begin(True)` / `spec_end()` exactly as the
  server does, and each prompt line now carries `N/M drafts accepted`. The final line names the
  mode too (`ALL PASS: token-exact with llama.cpp with KINDI_SPEC=mtp - ...`).
  `tests/test_verify_spec.py` (9 tests) pins the line in every state and drives `run()` with a
  stand-in engine and a one-prompt reference: with a mode it calls `spec_begin`/`spec_end` and
  compares tokens, without one it calls neither.
- **A2 (done 2026-11-17, PASS): mode A is exact.** `KINDI_TC=1 KINDI_MTP_HEAD=~/.kindi/models/
  kindi-mtp-2b-v1.npz kindi verify --spec mtp` on the 2B / RTX 4060 Ti, ctx 1024, 4 prompts x 40
  greedy tokens: **4/4 prompts, 160/160 tokens token-exact with llama.cpp**, 98/248 drafts accepted,
  203.5 tok/s against 279.0 plain (0.73x at this length, the same order as the 0.66x measured at 512
  tokens). The head is the registered file (sha256 `1b5c0c79…`); `docs/MTP.md` records the matrix, so
  its "same output" sentence is now gated rather than corrected.
- **A3 (done 2026-11-17, one cell blocked): every mode that can run here has a cell.** Measured on
  the 2B / RTX 4060 Ti, same 4x40 matrix: `ngram` 4/4 (51/152 drafts accepted, 435.3 tok/s),
  `draft2b` 4/4 (128/128, 311.1), `both` 4/4 (102/242, 276.2), `mtp` 4/4 (98/248, 203.5). B0/B2
  draft with the same 2B that is the target, so those acceptance numbers prove the path, not the 27B
  pairing. `dspine` has no cell: no DSpine directory exists on this host
  (`docs/MANUAL-HELP-NEEDED.md` row 7 is the owner action).
- **A4 (done 2026-11-17): a refusal is named.** A requested model-drafter mode that is not what
  attached is a refusal: `FAIL: mtp was requested but the effective mode is 0: the MTP head is not
  attached` and exit 2, before any prompt runs (measured with `--spec mtp` and no head). `draft2b`
  without `KINDI_SPEC_PACK` would resolve to `ngram`; that is refused as well, so a run cannot pass
  while testing a mode other than the one asked for. `auto` is exempt because choosing is its job.
- **A5 (standing, holds): the plain path is unchanged.** The plain run gains one line
  (`speculation: off (KINDI_SPEC=0)`) and its summary gains the suffix ` (speculation off)`; the
  `PASS`/`tokens/s` lines `tools/verify_matrix.py` parses (and the `ALL PASS: token-exact with
  llama.cpp` string `tests/test_cpu_avx_fallback.py` asserts) are unchanged. Measured: plain verify
  4/4, 279.0 tok/s on the 2B regardless of the new flag being absent.
- **A6 (done 2026-11-17): the regression matrix runs and scores the same modes.**
  `tools/verify_matrix.py` adds `--spec-modes` (default `ngram,mtp,draft2b,both`) on `--spec-models`
  (default `2b`) to the existing model x mode cells, as `<spec-base>-<spec>` (`tc-ngram`, ...;
  `--spec-base` default `tc`). Each cell passes `verify --spec <mode>` and the mode's files
  (`--mtp-head`, `--spec-pack`, `--draft-head`), and records `spec_requested`, `spec_effective`,
  `drafts_accepted` and `drafts_drafted` in the table, CSV and JSON. A requested mode that resolved
  to another is `refused`, checked before the generic exit-2/no-reference branch so a refused mode is
  never scored as a pass or a missing reference. A missing head/pack is a skip (printed, absent from
  the rows); a baseline that contains the cell then fails it as missing under `--fail-on-regression`.
  Eight tests in `tests/test_verify_matrix.py` cover the environment chaining for every base, the
  file variables, skip reasons, requested/effective/draft parsing, refusal ordering, the `--spec`
  flag in `run_cell`, a pass that never named the mode, and dry-run listing/skipping. Measured: the
  2B matrix with plain + all four spec cells passed 5/5 in one run on 2026-11-17 (4/4 prompts,
  160/160 tokens each); `both` also passed after its env was narrowed to `KINDI_SPEC_PACK` +
  `KINDI_SPEC_DRAFT_HEAD`. The 27B with the 2B drafter then passed `tc-ngram`, `tc-draft2b` and
  `tc-both` in a four-cell matrix (2026-11-17): each had the same verdict as the no-speculation
  27B cell, **3 prompts token-exact + 1 accepted llama.cpp tie at token 14 (gap 0.0064), 0 fail**,
  with the requested mode effective and 35/148, 112/162 and 90/211 drafts accepted; the tie is the
  existing 27B prompt-1 tie, not a new speculation difference ([RESULTS](../../benchmarks/2026-11-17-i7-8086k-rtx4060ti-27b-drafter/RESULTS.md)).
  Not verified: `dspine` (no weights); the 27B run is one pass with no repeats and is exact only
  under the accepted-tie rule, not a 4/4-token-exact result.

## Evidence

- Existing: `kindi/spec.py:1277` (`self.spec_mode = mode`, set by the server build only);
  `tools/verify_matrix.py` (mode matrix without a speculation mode); `docs/MTP.md` "Measured speed"
  ("The output of every mode was the same as without speculation").
- The gap in this round: mode A was measured for tok/s (0.66x) but never for exactness — the head
  was fixed and benchmarked, and the token-for-token check was not available.
- Related: `CURRENT-VS-KINDI-0.7.md` §41, `docs/MTP.md` "Measured 2026-11-17", `f934a55`.
- Implemented 2026-11-17: `verify.spec_state()` + `run()`'s spec branch, `verify --spec`, and the
  mode line on every run; `docs/MTP.md`'s "same output" sentence now cites the gate and the five-row
  matrix. Tests: `tests/test_verify_spec.py` (9), mutation-checked (ignoring the selected mode fails
  2, letting a refusal fall through fails 1). Not verified: `dspine` (weights absent, owner action),
  and no `both`/`draft2b` cell with an independent drafter (only the degenerate same-2B pairing ran).
