# REQ-0020: Intel Arc A770 (Alchemist/DG2) support via a SYCL/oneAPI backend

- Status: proposed

## Requirement

Kindi supports the Intel Arc A770 16 GB as a first-class platform: one
card, two cards, and CPU + Arc tandem, behind the same contract as the
NVIDIA cards (installer offer, `kindi verify` token-exact, prompt cache,
server contract, measured numbers in the support matrix). The design,
gates and milestones are `docs/INTEL-ARC.md` (M0 architecture audit done
2026-11-10); this requirement tracks the milestones, not the kernel
implementation detail.

2026-11-22: the A770 16 GB is **installed in the Windows test rig**. M1
hardware qualification is partly measured there: the card is visible at
16 GiB, the display class registers a Level Zero driver, the loader
enumerates one driver and one device, and the 2B/4B/9B CPU baselines are
token-exact 4/4. The Level Zero memory path also runs: `kindi intel-smoke`
round-trips 16 MiB through device and shared USM with zero mismatches. The
oneAPI/SYCL toolchain, the ReBAR/PCIe record and the llama.cpp SYCL
baseline are still missing, so M1 is not passed and no support claim
exists. M2 is partial: its memory/queue half is measured, and a
runtime-compiled OpenCL vector-add/GEMM passes exactly, while the SYCL
path (`libksycl.so`, device selection) is open. Windows is not the first
target; the installer, Docker images and GPU stack are Linux-first.

## Acceptance

- M1 (hardware qualification): one A770 16 GB on Linux, pinned
  oneAPI/SYCL/Level Zero toolchain, device visible at 16 GB, Resizable
  BAR and PCIe state recorded, CPU and llama.cpp SYCL baselines run.
  The arrival checklist is in `docs/INTEL-ARC.md`.
- M2 (backend smoke test): `libksycl.so`, USM, vector-add/GEMM and
  device selection run on the A770 with no CPU fallback. Status
  2026-11-22: the device/shared-USM memory path passes, and
  runtime-compiled OpenCL vector-add/GEMM are bit-exact with no CPU
  fallback (`kindi intel-cl`); `libksycl.so`, a SYCL kernel and Kindi
  device selection are open. Next step (planned 2026-11-23, not run): a SYCL
  vector-add smoke with oneAPI DPC++ on the Windows A770, exact over
  1,048,576/1/1,000,003 elements, with an explicit Level Zero selection and a
  negative no-fallback check; the plan and acceptance checks are in
  `docs/INTEL-ARC.md`.
- M3 (single-card 2B exact): plain engine, exact head, `kindi verify`
  4/4 token-exact; no fast/spec/TC/plan engine on this path.
- M4 (server and cache): non-stream/stream chat, prompt cache
  save/restore, health/metrics match M3 outputs.
- M5: 4B/9B/27B exact verify and fitted context measured.
- M6 (two cards): layer split, 27B exact, >=1.3x single-card at the
  same context, no exchange race.
- M7 (CPU+Arc tandem): exact, >=1.15x Arc-only or enables a
  model/context Arc-only cannot fit; otherwise a documented no-go.
- M8 (installer and support claim): installed setup passes the same
  checks as the NVIDIA rows, with no manual environment override.

## Evidence

- **M1, Windows host (2026-11-22):** `kindi intel-info` now reads Windows
  CIM/display-class data and enumerates Level Zero without filling a
  versioned device struct. Measured: Arc A770 `8086:56A0`, 16,384 MiB,
  display driver 32.0.101.9175, Level Zero loader 1.33.1, `zeInit` 0 with
  1 driver and 1 device; CPU `verify` 4/4 token-exact for 2B/4B/9B at
  22.2/11.1/6.5 tok/s (ctx 1,024). Not met: oneAPI/SYCL (`sycl-ls`),
  ReBAR, PCIe link state, llama.cpp SYCL baseline. Evidence:
  `docs/benchmarks/2026-11-22-i7-8086k-arc-a770/`. This is hardware
  qualification, not M1 passed and not a support claim.
- **M2 kernel path, Windows host (2026-11-22):**
  `python -m kindi intel-cl --json` compiles and runs an OpenCL C
  vector-add (1,048,576 elements) and a 128x128 GEMM (5 launches) through
  the installed OpenCL 3.0 NEO runtime, with 0 mismatches against an
  exact host reference in 6.5 ms and 0.666 ms (31.5 GFLOP/s wall); the
  driver reports 512 compute units, 15,932 MiB and driver
  32.0.101.9175. Three API findings are recorded in the run page. This is
  the kernel/GEMM half measured through OpenCL, not SYCL: no
  `libksycl.so`, Kindi backend, engine, model or support claim. Evidence:
  `docs/benchmarks/2026-11-22-i7-8086k-arc-a770/cl-smoke.json`.
- **M2 memory path, Windows host (2026-11-22):**
  `python -m kindi intel-smoke --mib 16 --json` passes through Level Zero
  loader 1.33.1: one driver / one device, device-USM allocation,
  shared-USM staging, a command list and a synchronous queue, and a
  16 MiB host -> device -> host round trip with 0 mismatches in 11.6 ms.
  Two driver behaviors are recorded: `zeMemCopy` is absent from this
  loader, so copies use a command list; and queue group 0 advertises
  COPY but silently ignores copy commands, while the copy-only group 1
  executes them (selection is now capability-based). This is the memory
  and queue path only: no kernel, GEMM, model, engine or CPU fallback.
  M2 is not passed. Evidence:
  `docs/benchmarks/2026-11-22-i7-8086k-arc-a770/l0-smoke.json`.
- **M2 packed ternary GEMV probe, Windows host (2026-11-23):**
  `python -m kindi intel-ternary --rows 64 --cols 1024 --json` (and
  128x4096, 512x4096) builds the matrix in the pack's 4-trit/byte
  `[column/4][row]` layout with one fp16 scale per 128 weights, runs one
  OpenCL C GEMV on the A770 and matches a host reference bit for bit: 0
  mismatches on every row at all three shapes (0.944/2.470/2.437 ms for
  five launches, 0.694/2.123/8.604 GFLOP/s wall). Probe only: no
  activation quantization, SYCL, backend, model or support claim.
  Evidence: `docs/benchmarks/2026-11-23-i7-8086k-arc-a770/`.
- **M2 phase-parallel packed ternary GEMV, Windows host (2026-11-24):**
  the probe splits the 128-weight phase axis (work-item `(row, part)`
  owns the phases with `ph % parts == part`, then a reduce kernel adds
  the parts), because one work-item per row used 512 of 512 EUs' worth of
  work-items. `--parts` defaults to one part per phase capped at 64;
  `--parts 1` keeps the 2026-11-23 shape. Bit-exact at every shape, 20
  launches, median of three runs: 512x4096 1.111 ms / 75.54 GFLOP/s,
  1024x8192 1.224 ms / 274.12, 2048x4096 1.152 ms / 291.15, 4096x4096
  1.577 ms / 425.60, each 5.75x-14.14x the one-work-item shape (64x1024
  gains 2.68x because launch overhead dominates there). Exactness is
  argued from the values and checked on the host before every launch:
  `kindi.intel_ternary.partials` refuses a shape where the split is not
  exact. Still the on-disk pack layout with an unquantized activation, no
  lane repack, SYCL, backend, model or support claim. Evidence:
  `docs/benchmarks/2026-11-24-i7-8086k-arc-a770-parallel-gemv/`.
- The A770 was purchased 2026-11-15 and is installed in the Windows test
  rig; no milestone is passed and the SYCL half is unevidenced.
  `docs/SUPPORT-MATRIX.md` renders the A770 as
  `not measured`; `docs/CARDS.md` and the installer must not list Arc
  as supported until M8 passes.
- Record every M1/M2 run (device identity, driver/oneAPI versions,
  ReBAR/PCIe state, baseline numbers) in
  `docs/benchmarks/<date>-<host>-arc-a770/` and fold later
  verify_matrix runs into `docs/benchmarks/card-results.json` under the
  `arc-a770` slug.
