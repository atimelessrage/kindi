# REQ-0020: Intel Arc A770 (Alchemist/DG2) support via a SYCL/oneAPI backend

- Status: proposed

## Requirement

Kindi supports the Intel Arc A770 16 GB as a first-class platform: one
card, two cards, and CPU + Arc tandem, behind the same contract as the
NVIDIA cards (installer offer, `kindi verify` token-exact, prompt cache,
server contract, measured numbers in the support matrix). The design,
gates and milestones are `docs/INTEL-ARC.md` (M0 architecture audit done
2026-11-10); this requirement tracks the milestones, not the kernel
implementation detail.

2026-11-15: one A770 16 GB has been **purchased and is in transit**; it
is not installed yet. That unblocks M1 (hardware qualification) the day
it arrives, but no Arc code has been executed anywhere, so no support
claim exists. Windows is not the first target; the installer, Docker
images and GPU stack are Linux-first.

## Acceptance

- M1 (hardware qualification): one A770 16 GB on Linux, pinned
  oneAPI/SYCL/Level Zero toolchain, device visible at 16 GB, Resizable
  BAR and PCIe state recorded, CPU and llama.cpp SYCL baselines run.
  The arrival checklist is in `docs/INTEL-ARC.md`.
- M2 (backend smoke test): `libksycl.so`, USM, vector-add/GEMM and
  device selection run on the A770 with no CPU fallback.
- M3 (single-card 2B exact): plain engine, exact head, `kindi verify`
  4/4 token-exact; no fast/spec/TC/plan engine on this path.
- M4 (server and cache): non-stream/stream chat, prompt cache
  save/restore, health/metrics match M3 outputs.
- M5: 4B/9B/27B exact verify and fitted context measured.
- M6 (two cards): layer split, 27B exact, >=1.3x single-card at the
  same context, no exchange race.
- M7 (CPU+Arc tandem): exact, >=1.15x Arc-only or enables a
  model/context Arc-only cannot fit; otherwise a documented no-go.
- M8 (installer and support claim): installed setup passes the same
  checks as the NVIDIA rows, with no manual environment override.

## Evidence

- No Arc hardware was present when this requirement was written
  (purchased 2026-11-15, in transit, not installed), so every milestone
  above is unevidenced. `docs/SUPPORT-MATRIX.md` renders the A770 as
  `not measured`; `docs/CARDS.md` and the installer must not list Arc
  as supported until M8 passes.
- When M1 runs, record the run (device identity, driver/oneAPI
  versions, ReBAR/PCIe state, baseline numbers) in
  `docs/benchmarks/<date>-<host>-arc-a770/` and fold later
  verify_matrix runs into `docs/benchmarks/card-results.json` under the
  `arc-a770` slug.
