# REQ-0028: An Anthropic Messages endpoint for agent harnesses

- Status: active
- Implementation: the endpoint landed 2026-11-24 (A1, A2, A3's app-level gate and A4's code gate
  done, and A4's live pack run passed the same day on the CPU engine); A3's real Claude Code run
  stays open, so it is *available*, not *compatible*

## Requirement

Agent harnesses are split by API dialect: Ollama and llama.cpp speak OpenAI shapes, while Claude Code
speaks Anthropic's `/v1/messages`. A local engine that offers only the OpenAI shape needs a proxy
before that harness can use it.

`kindi serve` must accept Anthropic-shaped requests and answer them from the same engine path the
OpenAI chat endpoint uses, with no decoding change: the tokens are the ones `kindi verify` already
pins.

## Acceptance

- **A1 (done 2026-11-24): the endpoint exists and translates.** `POST /v1/messages` with `model`, `max_tokens`,
  `system`, `messages` (content as a string or a block list), `tools`, `temperature`, `top_p`,
  `top_k`, `stop_sequences` and `stream` maps onto the existing chat request. It returns the
  Anthropic envelope (`id`, `type: message`, `role: assistant`, `content` blocks, `stop_reason`,
  `usage`) or, with `stream: true`, the SSE event sequence `message_start` → `content_block_start`
  → `content_block_delta`(s) → `content_block_stop` → `message_delta` → `message_stop`.
  **Evidence:** `kindi/api/anthropic.py` (`to_chat`, `message`, `stream`) and the route in
  `kindi/server.py::create_app`; `tests/test_anthropic.py` pins the field mapping, the envelope, the
  stop-reason mapping and the exact SSE order. Auth accepts `x-api-key` (Claude Code) and a bearer
  token; every error is the Anthropic envelope, never a 500.
- **A2 (done 2026-11-24): tools round-trip.** A request with a `tools` list and a reply that produces a tool call
  comes back as a `tool_use` block, and a later turn's `tool_result` block goes in as the engine's
  tool message. A refusal or a malformed request is an Anthropic-shaped `error` body, not a 500.
  **Evidence:** `test_a_tool_call_round_trips_through_the_endpoint` (the call comes back as a
  `tool_use` block with parsed `input`, and the next turn's `tool_result` reaches the engine as a
  `tool` message); `test_a_malformed_request_is_an_anthropic_error_not_a_500`; an `image` or
  `document` block is refused by name rather than dropped.
- **A3 (app-level gate done 2026-11-24; harness run open): the gate.** An app-level test posts a Claude-Code-shaped request through `create_app`
  (stub engine, no GPU) and asserts the envelope, the SSE event order and the tool round-trip; and a
  real harness run — Claude Code pointed at `kindi serve --port 8093` — answers one prompt, recorded
  with its command. Until that run exists, the endpoint is called *available*, not *compatible*.
  **Evidence:** the app-level half is `tests/test_anthropic.py` (14 translation/response/stream checks
  and 5 `create_app` checks with a stub engine, no GPU or pack). The harness run needs a Claude Code
  install and a served model, so it stays owner-bound.
- **A4 (done 2026-11-24: code gate and live pack run): no decoding change.** The translation is a
  request/response adapter; `kindi verify` and its reference matrix are unaffected, and `KINDI_SPEC`
  behaviour is the same through either dialect. **Evidence:** `kindi selftest` already posts the same
  greedy prompt (`temperature 0`) through `/v1/chat/completions` and `/v1/messages`; it now compares the
  two answers and fails when the text or the completion-token count differs
  (`kindi/selftest.py::_dialects_agree`, in both the in-process and `--url` modes), recording
  `dialects{same_text, same_tokens, chat_text, anthropic_text}` in its JSON. `tests/test_selftest.py`
  pins the agreeing case and a drifting engine (a different reply on the second request fails the run
  with "changed decoding") plus a served server that answers the dialects differently. **Live run
  (2026-11-24):** `KINDI_DEVICE=cpu kindi selftest --max-tokens 8` on the real 2B pack loaded the
  engine and reported `dialects agree (2 token(s), 5 chars)` — `/health` 200, `/v1/chat/completions`
  and `/v1/messages` decoded the same two tokens (the model stopped at 2), exit 0, 24.1 s including
  the 25 s-class CPU load. The earlier block was the CPU engine's missing compiler, which turned out
  to be installed but off `PATH` (`kindi/cpu.py::_find_cc`; `docs/MANUAL-HELP-NEEDED.md` §3b). Greedy
  repeats are gated separately (ten identical completions).

## Evidence

- Source of the idea (not evidence): the external knowledge base's `docs/BIGMOEONEDGE.md` §5 names
  Anthropic `/v1/messages` as that engine's "sleeper feature" because Claude Code and the harness
  ranking expect it `[P]`. Recorded in `docs/development/AI-INVENTORY-SCAN.md`, scan 2026-11-17.
- What exists: `kindi/server.py` is OpenAI-shaped only - chat completions, `/v1/models`,
  `/api/tags`, `/health`, `/metrics`; there is no `/v1/messages`, `x-api-key` handling or content-block
  translation anywhere in `kindi/` (grep 2026-11-17). The structured-output and tool-call parsers
  (`kindi/tools.py`, `kindi/jsongrammar.py`) already produce the blocks a translation would emit.
- Implemented 2026-11-24: `kindi/api/anthropic.py` is the whole dialect (request, envelope, SSE) as
  pure dict/string transforms with no FastAPI import, so it unit-tests on a CPU-only host; `server.py`
  wires it to the same `run_generate` path and now shares one SSE relay (`_relay`) between the OpenAI
  and Anthropic streaming routes instead of two copies. `docs/API.md` documents the field mapping and
  what is not claimed; the live-work row in `docs/ROADMAP.md` and `CHANGELOG.md` record it.
