# REQ-0028: An Anthropic Messages endpoint for agent harnesses

- Status: proposed

## Requirement

Agent harnesses are split by API dialect: Ollama and llama.cpp speak OpenAI shapes, while Claude Code
speaks Anthropic's `/v1/messages`. A local engine that offers only the OpenAI shape needs a proxy
before that harness can use it.

`kindi serve` must accept Anthropic-shaped requests and answer them from the same engine path the
OpenAI chat endpoint uses, with no decoding change: the tokens are the ones `kindi verify` already
pins.

## Acceptance

- **A1 (open): the endpoint exists and translates.** `POST /v1/messages` with `model`, `max_tokens`,
  `system`, `messages` (content as a string or a block list), `tools`, `temperature`, `top_p`,
  `top_k`, `stop_sequences` and `stream` maps onto the existing chat request. It returns the
  Anthropic envelope (`id`, `type: message`, `role: assistant`, `content` blocks, `stop_reason`,
  `usage`) or, with `stream: true`, the SSE event sequence `message_start` → `content_block_start`
  → `content_block_delta`(s) → `content_block_stop` → `message_delta` → `message_stop`.
- **A2 (open): tools round-trip.** A request with a `tools` list and a reply that produces a tool call
  comes back as a `tool_use` block, and a later turn's `tool_result` block goes in as the engine's
  tool message. A refusal or a malformed request is an Anthropic-shaped `error` body, not a 500.
- **A3 (open): the gate.** An app-level test posts a Claude-Code-shaped request through `create_app`
  (stub engine, no GPU) and asserts the envelope, the SSE event order and the tool round-trip; and a
  real harness run — Claude Code pointed at `kindi serve --port 8093` — answers one prompt, recorded
  with its command. Until that run exists, the endpoint is called *available*, not *compatible*.
- **A4 (standing): no decoding change.** The translation is a request/response adapter; `kindi
  verify` and its reference matrix are unaffected, and `KINDI_SPEC` behaviour is the same through
  either dialect.

## Evidence

- Source of the idea (not evidence): the external knowledge base's `docs/BIGMOEONEDGE.md` §5 names
  Anthropic `/v1/messages` as that engine's "sleeper feature" because Claude Code and the harness
  ranking expect it `[P]`. Recorded in `docs/development/AI-INVENTORY-SCAN.md`, scan 2026-11-17.
- What exists: `kindi/server.py` is OpenAI-shaped only - chat completions, `/v1/models`,
  `/api/tags`, `/health`, `/metrics`; there is no `/v1/messages`, `x-api-key` handling or content-block
  translation anywhere in `kindi/` (grep 2026-11-17). The structured-output and tool-call parsers
  (`kindi/tools.py`, `kindi/jsongrammar.py`) already produce the blocks a translation would emit.
- Not started. The gate is CPU-testable except A3's harness run, which needs a Claude Code install on
  a machine that can reach the server.
