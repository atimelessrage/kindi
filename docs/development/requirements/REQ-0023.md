# REQ-0023: A kernel launch contract checked for every call site

- Status: proposed

## Requirement

Every kernel a Python call site launches must be launched with the arguments and the grid/block
shape its `.cu` declaration requires. A mismatch must fail in the CPU suite, not in a log line at
runtime.

This exists because of a measured failure: `k_rmsfold_qT` gained a trailing `hp` in 0.5.0,
`kindi/mtp.py` was not updated, and the MTP head's CUDA graph therefore never built
(`cuGraphAddKernelNode failed (1)`). The engine logged one line, `/health` still said drafting was
enabled, and mode A was dead on the tensor-core layout for four releases. A short argument tuple is
not a Python error, so no existing gate could see it. `tests/test_kernel_arity.py` closed the case
for that one kernel; the requirement is the general rule.

## Acceptance

- **A1 (done 2026-11-17): the check covers every graph-built call site.** Every `Plan.add(...)` /
  `E(...)` kernel launch in `kindi/spec.py`, `kindi/dspine.py`, `kindi/mtp.py` and `kindi/tp.py` is
  compared against its kernel's declared parameter count: **105 call sites** are measured (spec 26,
  dspine 37, mtp 3, tp 39) and **37 unrunnable-by-parser sites are pinned in `UNRESOLVED_SITES`** with
  a reason each (a kernel held in a variable, list element, dict lookup, `getattr`, or a conditional;
  an argument tuple built by a helper or by `tuple(...) + ...`), so a new dynamic launch fails the
  test until somebody classifies it. The DSpine graph is now reached: its `kf["..."]` lookups are
  resolved from the literal iterable that builds `self.kf`, and `self.k` / `self.k8 if ... else
  self.k16` from their `get_function(...)` assignments (both suffix variants in the latter). Only the
  `_Planner.__call__` wrapper and `self.hmv` remain pinned in dspine.py.
  Two sub-contracts the work uncovered and now encodes: (a) a name can be declared with **different
  arities per backend** - `k_tc_q8` takes 7 parameters on HIP/Pascal and 8 on CUDA, and the call site
  adds `hp` behind `() if is_hip or pascal else (hp,)` - so the contract is the declared *set*, not a
  single number; (b) the token-batched `k_*_T` kernels are not in any `.cu` file: `kindi/chunk.py`
  `_wrappers` generates them as `name(params, int T_, one stride per pointer)`, and the checker
  derives those arities from the base declaration (`k_argmax_T` is 6/7 that way, and `mtp.py`'s call
  is measured, not excused); (c) a conditional argument tuple is checked branch by branch: `(a..f)
  if cond else (a..g)` against a 7-parameter kernel contributes both 6 and 7, and the 6 branch fails,
  because taking the largest branch's count would let the wrong branch pass
  (`test_every_argument_branch_must_match_the_kernel`).
- **A2 (block half done 2026-11-24; grid half open): a grid/block literal is checked where the
  kernel's declaration constrains it.** `test_no_launch_asks_for_more_threads_than_its_kernel_declares`
  parses every `__global__ void __launch_bounds__(N[, M]) k_*(` in `kindi/*.cu`/`*.cuh` (96 kernels
  declare a ceiling) and compares it with the literal block tuple at each launch: **28 (site, kernel)
  pairs** are measured and **135 sites are unresolved**, because 96 launch a kernel that declares no
  bound at all and the rest name the kernel or the block through a variable, `getattr` or a runtime
  width (`(HK,)`, `(32 * nw,)`). Both counts are pinned, so a new launch is reviewed once. Only the
  first `__launch_bounds__` argument is a contract: the second is a minimum-blocks occupancy hint.
  A name declared more than once keeps every bound and a launch must fit the strictest, since the
  caller cannot say which variant it got. A 1024-thread launch against a 256-thread kernel is
  reported as `k_big asks 1024 > 256` (proof the check is not vacuous).
  **The grid half stays open:** a grid of zero launches nothing and raises nothing, but every grid
  element is a runtime expression (`(R // 16,)`, `(-(-(R // 16) // 32), sp)`), so a static check would
  have to reason about the model's dimensions. The honest lever there is a runtime assertion in the
  planner (once, per plan) on a GPU host.
- **A3 (done 2026-11-17): the test is proven non-vacuous per call site.**
  `test_every_checked_site_is_detected_when_mutated` writes a mutated copy of the module for every one
  of the 105 measured sites and requires the checker to report that site: it first drops the last
  argument (the shape of the real `hp` bug), and where a dual-arity kernel makes that land legally on
  the other declaration it falls back to an empty argument tuple. A site whose mutation is not caught
  fails the test by name. This also covers the original defect: `mtp.py:208` (`k_rmsfold_qT`, 20/20)
  is one of the measured sites.
- **A4 (standing): CPU-only.** No GPU, no compiler, no pack: the test parses source text at suite
  time, so it runs in the ordinary `pytest -q` gate.

## Evidence

-   `tests/test_kernel_arity.py` (8 tests, 2026-11-17): `_kernel_arity` reads every
  `extern "C" __global__ void [__launch_bounds__(N)] k_*(...)` in `kindi/*.cu`/`*.cuh`, adds the
  generated `k_*_T` wrapper arities from `kindi/chunk.py::_wrappers`, and `check_module` compares each
  of the 105 resolvable launches; `_counts` keeps every possible argument count (tuple/list length,
  `+` cross-product, `if`/`else` union); `test_unresolved_call_sites_are_listed_not_skipped` pins the 37
  unresolvable ones with reasons; `test_measured_sites_are_the_pinned_count` pins the coverage at 105
  so a silent drop fails too; `test_every_checked_site_is_detected_when_mutated` is the per-site
  mutation proof.
- The failure it prevents: `CURRENT-VS-KINDI-0.7.md` §41, `docs/MTP.md` "Measured 2026-11-17",
  fixed in `f934a55`.
- Not yet covered: grid literals (A2's other half, see there), the 135 launches whose block or kernel
  is dynamic, and the 37 remaining pinned dynamic argument sites, which would need a different
  technique (`getattr`/callable variables or run-time assertions). The block half is in
  `tests/test_kernel_arity.py::_check_block_sizes` (2026-11-24). The DSpine `kf`
  table and the `self.k`/`self.k8`/`self.k16` assignments are now resolved statically; `self.hmv` and
  the `_Planner` wrapper parameter are the two dspine sites that remain.
