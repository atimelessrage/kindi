# REQ-0023: A kernel launch contract checked for every call site

- Status: proposed

## Requirement

Every kernel a Python call site launches must be launched with the arguments and the grid/block
shape its `.cu` declaration requires. A mismatch must fail in the CPU suite, not in a log line at
runtime.

This exists because of a measured failure: `k_rmsfold_qT` gained a trailing `hp` in 0.5.0,
`kindi/mtp.py` was not updated, and the MTP head's CUDA graph therefore never built
(`cuGraphAddKernelNode failed (1)`). The engine logged one line, `/health` still said drafting was
enabled, and mode A was dead on the tensor-core layout for four releases. A short argument tuple is
not a Python error, so no existing gate could see it. `tests/test_kernel_arity.py` closed the case
for that one kernel; the requirement is the general rule.

## Acceptance

- **A1 (open): the check covers every graph-built call site.** Every `Plan.add(...)` / `E(...)`
  kernel launch in `kindi/spec.py`, `kindi/dspine.py`, `kindi/mtp.py` and `kindi/tp.py` is compared
  against its kernel's `.cu` parameter count; a call site the parser cannot count statically is
  listed explicitly (not silently skipped), with the reason.
- **A2 (open): a grid/block literal is checked where the kernel's declaration constrains it.** At
  minimum: a block dimension over 1024 threads, or a block shape that disagrees with the kernel's
  own `blockDim` assumption where the source states it, is a test failure.
- **A3 (open): the test is proven non-vacuous per kernel.** For each covered kernel, the mutation
  check (drop one argument from a call site on a copy, expect exactly that test to fail) is recorded
  at least once in the round that added the coverage.
- **A4 (standing): CPU-only.** No GPU, no compiler, no pack: the test parses source text at suite
  time, so it runs in the ordinary `pytest -q` gate.

## Evidence

- Today's head start: `tests/test_kernel_arity.py` (4 tests) — parses `k_rmsfold_qT`'s 20 parameters
  from `kindi/tcf.cu` and the argument tuple of three call sites (`kindi/mtp.py:208`,
  `kindi/dspine.py:362`, `kindi/spec.py:733`); removing `hp` from `mtp.py` fails exactly that
  parameter, and restoring it passes (2026-11-17).
- The failure it prevents: `CURRENT-VS-KINDI-0.6.md` §41, `docs/MTP.md` "Measured 2026-11-17",
  fixed in `d1d23f2`.
- Not yet covered: every other kernel, every other call site, grid/block literals.
