# REQ-0019: Backend plugin interface (contract, registry, adapters)

- Status: experimental

## Requirement

Adding a model becomes a contained change: one backend module plus docs, with
no edits to the server or the CLI. The four shipped engines (Bonsai,
Nanbeige, Nemotron Lightning, DeepSeek V4.1) sit behind one contract, and a
fallback path gives Kindi coverage of arbitrary GGUF models. This is the
Feature 4 half of the delegation plan; the repo map for it is
`docs/dev/REPO-MAP.md` (T0).

## Acceptance

- T4.1 (done): a dependency-free contract (`kindi/backends/base.py`:
  capabilities, sampling params, generation events, cancellation), a
  registry (`kindi/backends/registry.py`) that resolves by model id and by
  GGUF `general.architecture` metadata and loads external backends through
  `KINDI_BACKEND_MODULES`, and a deterministic `FakeBackend`
  (`kindi/backends/fake.py`) usable on a CPU-only host. Contract tests pass
  over the fake backend and auto-extend to every registered backend.
- T4.2 (planned): the four existing engines ported as thin adapters with
  `KINDI_LEGACY_ENGINE_PATH=1` as the safety valve; `kindi verify` and
  `kindi bench` match the pre-port numbers on the agreed cards.
- T4.3 (done 2026-11-15): `docs/BACKENDS.md` is the authoring guide and
  `kindi backends [--json]` lists registered backends, including external
  backends loaded from `KINDI_BACKEND_MODULES`.
- T4.4/T4.5 (planned, decision-gated): a generic fallback — llama.cpp proxy
  backend (recommended) or a native generic backend (design only, GPU kernel
  work with the maintainer). No arbitrary-GGUF claim until one of them lands
  and passes `kindi verify` or the proxy gate.

## Evidence

- `tests/backends/test_registry.py`, `tests/backends/test_contract.py` and
  `tests/test_backends_cli.py` pass CPU-only (Python 3.6-compatible syntax;
  the shared code must import on the CUDA image's Python 3.6). The CLI was
  smoke-tested: `kindi backends` lists `fake` on CPU, and `--json` emits the
  registry rows.
- `docs/dev/REPO-MAP.md` resolves every `[LOCATE]` in the plan and lists the
  FROZEN files (GPU kernels, weight conversion, model numerics, sampler
  core). Serve-time engine selection today is the pack manifest `backend`
  key, written at convert time from the GGUF architecture.
- No engine adapter exists yet, so `resolve` serves only the fake backend and
  externally registered backends and says so (T4.2 is the next task).
