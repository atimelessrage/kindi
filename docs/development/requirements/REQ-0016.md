# REQ-0016: Chat session history with triage, tags, and raw-markdown export

- Status: experimental

## Requirement

`kindi chat` turns are stored as sessions on the host under
`<state_dir>/sessions/` (one JSON file each). A session has a title, its
ordered messages, tags, and a triage status (`open`, `needs-review`,
`resolved`). Sessions can be listed, filtered by status or tag, moved
through triage, tagged, and exported to raw markdown — the exact message
text verbatim with a small header, never reflowed or paraphrased — and
that export format can be imported back.

## Acceptance

- `kindi/sessions.py` `SessionStore` creates, reads, appends, retags,
  re-statuses, lists (status/tag filtered), and triages sessions; an
  invalid status raises a named error (pinned by `tests/test_sessions.py`).
- Export writes the message text byte for byte into the markdown, and
  `import_markdown` of that export returns the same title, tags, order,
  and content (round-trip test).
- `kindi sessions list|show|export|triage|tag|status|import` runs
  host-only (no pack or GPU) and prints one line per session; `--state-dir`
  picks the store.
- `kindi chat` saves the session on exit (or EOF) unless `--no-record` is
  given; a chat with no user/assistant turns saves nothing.
- The HTTP server exposes the same store (no engine involved):
  `GET /sessions` (status/tag filters), `GET /sessions/<id>`,
  `GET /sessions/<id>/export` (raw markdown), `POST /sessions/<id>/status`
  and `POST /sessions/<id>/tags`, all behind the API key when one is set.
  Ids are the store's 12-hex ids; any other id is a 400, never a file read.

## Evidence

- `kindi/sessions.py`: the store; `kindi/__main__.py`: `cmd_sessions`,
  `_record_chat`, and the `sessions` + `--no-record` CLI wiring.
- `tests/test_sessions.py`: record/list/get, triage transitions,
  tag slugify/dedupe/filter, raw-markdown round trip, CLI round trip.
- Live CLI smoke 2026-11-14: import from stdin, triage listing, and export
  produced `2026-11-15-demo.md` with the exact input text.
- **Server endpoints landed 2026-11-15:** `kindi/server.py` `create_app`
  (host-only routes over `SessionStore` under `state_dir/sessions`; auth,
  enveloped 400/404, traversal-safe id check) and
  `tests/test_server_sessions.py` (list/get/filter/export, status+tag round
  trip, missing/traversal ids, API-key gating) — 55 tests pass together with
  `test_server.py` and `test_sessions.py`.
- **Concurrency hardening 2026-11-15:** the routes share one
  `threading.Lock` (each request builds its own `SessionStore`, so a lock
  on the store would not serialize anything), the store writes to unique
  tmp files, and `list()` closes its file handles. A concurrent
  tag+status test now pins that both updates survive
  (`tests/test_server_sessions.py`).
