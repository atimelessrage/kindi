# REQ-0018: Agent-grade API: structured output, tool-call conformance, concurrency

- Status: proposed

## Requirement

The server must work as a drop-in backend for agent frameworks, not only as a fast chat
endpoint: constrained output, tool calls that conform per model, and request handling that
does not collapse under concurrent clients. The 0.6.0 additions (token counting, sessions,
priorities, progress comments) are the base; this requirement covers the next layer.

## Acceptance

- A request may constrain the reply to a JSON schema (`response_format` with `json_schema`) or
  a grammar; the returned content parses against the schema. This is decode-side constraint,
  not a post-hoc prompt. **JSON schema + json_object landed 2026-11-15** (dense path);
  arbitrary grammars (GBNF) stay to a later slice.
- Every shipped backend (Bonsai XML, Gemma 4 native, DeepSeek DSML, Nemotron XML) has a
  tool-call conformance suite: valid calls parse to OpenAI `tool_calls`, truncated calls
  never leak raw markup into the reply, and repeat/duplicate calls are handled as the
  backend documents. The DeepSeek cut-off fix (`dsv41_server.py`) is the motivating case.
- The server either serves concurrent requests on separate engine state, or keeps the
  single-active-request contract with bounded queueing (REQ-0005) and says so in the docs.
  Continuous batching stays NO-GO until a new Phase-0 spike passes its 1.5x gate
  (`docs/CONTINUOUS-BATCHING.md`); a concurrency claim must not be made on the failed spike.
- Metrics for monitoring stay in place (`/metrics`, JSON access log) and grow with any new
  path (conformance failures, batch stats).

## Evidence

- **Tool-call conformance suite landed 2026-11-15:** `tests/test_tool_call_conformance.py`
  (18 tests over Gemma 4 native, Nanbeige/Lightning XML+JSON, and DeepSeek DSML
  truncated blocks, alongside the Bonsai tests in `tests/test_tool_calls.py`): valid
  calls parse to OpenAI `tool_calls` with JSON-string arguments; truncated and
  malformed calls stay in content / return unclosed partials without leaking raw
  markup; quoted examples and calls for unoffered tools are dropped; DeepSeek
  cut-inside-value returns the name + unclosed argument start (never parses).
  Wire-format details (bare DSML function names, `>\n` after the invoke tag)
  verified against sglang/vLLM DSML references. All 23 tool-call tests pass.
- **Unsupported-field rejection landed 2026-11-15 (decision D2):**
  `kindi/server.py` rejects `n` values other than 1 and any
  `response_format` whose type is not `text` (including `json_schema` and
  `json_object`) with an enveloped 400, before the engine or prompt cache
  is touched; `n = 1` and `response_format: {"type": "text"}` remain
  accepted. Covered by the malformed-request cases in
  `tests/test_server.py` and the default-acceptance test.
- **The envelope now names the field 2026-11-15:** `RequestError` carries
  an optional `param` and the handlers surface it, so the D2 rejections
  (and the `logprobs` rejection) return `param: "n"` / `"response_format"`
  / `"logprobs"` instead of `null` (`test_unsupported_fields_name_their_param`).
- **JSON-schema constrained decoding landed 2026-11-15:** `kindi/jsongrammar.py`
  (schema-ordered deterministic automaton, `advance`/`done`, full-vocabulary allowed
  set cached per state — enumeration over the 248K Qwen vocab measured ~0.6 s) and
  `kindi/sampling.py`'s `allowed` intersection;   `kindi/server.py` accepts
  `json_object`/`json_schema` (grammar/unknown types and malformed schemas stay
  enveloped 400, tools with structured output rejected). The grammar-constrained
  loop is covered end to end CPU-only (the `_StopTok` harness: scripted picks must
  stay inside each pick's allowed set, the finished content parses as JSON).
  The dense path only (the Gemma 4 path keeps its `CallGrammar`).
  `grammar`-typed response_format and GBNF stay rejected.
- **GPU gate (2026-11-15, RTX 4060 Ti):** 2B `{"name": "Alex", "age": 28}` and
  `json_object` `{"city": "New York"}`, 9B with an array property — all parse
  against the schema, keys in schema order, `finish: stop`. The first 2B run
  surfaced a dead automaton state (`otail` accepting `,` with no properties
  left; empty allowed set) plus two more automaton dead-corners of the same class
  (number prefix language, required-before prefix in key buffers) — all fixed and
  pinned by tests.
- Still open: constrained decoding on the Gemma 4 path (its tool-call grammar is a
  separate precedent); a real concurrency story beyond REQ-0005's bounded queue
  (continuous batching stays NO-GO until a new Phase-0 spike passes 1.5x).
  Current state otherwise: tool calls exist per backend (`kindi/chat.py`,
  `kindi/gemma4_tools.py`, `kindi/dsv41_server.py`, `kindi/lightning_gen.py`).
- Gate before any support claim: schema-constrained replies parse for the 2B/9B; the
  conformance suite fails on a deliberately malformed call; concurrent requests either
  interleave or queue bounded, with `/metrics` showing it.
