# REQ-0014: FP8 E4M3 K/V cache, decided by the KLD gate

- Status: experimental

## Requirement

`KINDI_KV=fp8` stores K and V as FP8 E4M3 behind an explicit opt-in, decided by
the `kindi kld` quality gate (roadmap #8, `docs/ROADMAP.md`): it may only be
described as distribution-lossless if its KLD is no worse than the q8_0 row,
4/4 exact against the fp16 reference at verify length on tensor-core hardware,
and its peak is measured against q8_0. The host-side f32→FP8 conversion used by
that cache must be the same reference codec the CUDA kernels implement.

## Acceptance

- The host codec `f32_to_fp8` in `kindi/dtypes.py` encodes E4M3 and E5M2
  round-to-nearest, ties to even, with E4M3 saturation at 448 and E5M2
  infinities; every finite encoded pattern round-trips through `fp8_to_f32`
  exactly (pinned by `tests/test_dtypes.py`).
- `KINDI_KV=fp8` refuses without the experimental opt-in and names the gate
  result as the reason.
- A `kindi kld` row for the fp8 cache is recorded at 2K and 8K on the 2B; the
  row must beat the q8_0 row (2.07–2.74e-07 nats) to be called lossless.
- Until that run exists, no support claim, catalog entry, or default profile
  uses `fp8`.

## Evidence

- `kindi/dtypes.py`: `f32_to_fp8` host reference (encode side added 2026-11-14;
  decode already present).
- `tests/test_dtypes.py`: all-pattern round-trip, named values, saturation,
  tie-to-even, and subnormal rounding.
- The KLD gate itself is recorded in `docs/benchmarks/2026-11-14-i7-8086k-rtx4060ti-kld-2b/`
  (q8_0 row) with the fp8 row pending a real run.
