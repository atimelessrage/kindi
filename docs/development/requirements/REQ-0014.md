# REQ-0014: FP8 E4M3 K/V cache, decided by the KLD gate

- Status: experimental

## Requirement

`KINDI_KV=fp8` stores K and V as FP8 E4M3 behind an explicit opt-in, decided by
the `kindi kld` quality gate (roadmap #8, `docs/ROADMAP.md`): it may only be
described as distribution-lossless if its KLD is no worse than the q8_0 row,
4/4 exact against the fp16 reference at verify length on tensor-core hardware,
and its peak is measured against q8_0. The host-side f32→FP8 conversion used by
that cache must be the same reference codec the CUDA kernels implement.

## Acceptance

- The host codec `f32_to_fp8` in `kindi/dtypes.py` encodes E4M3 and E5M2
  round-to-nearest, ties to even, with E4M3 saturation at 448 and E5M2
  infinities; every finite encoded pattern round-trips through `fp8_to_f32`
  exactly (pinned by `tests/test_dtypes.py`).
- `KINDI_KV=fp8` refuses without the experimental opt-in and names the gate
  result as the reason.
- The decode cache is implemented in the plan engine (`kindi/kindi.cu`:
  `k_store_fp8`, `k_attn_sf8t`, `k_attn_vf8w`) with the q8_0 layout (one E4M3
  byte per value and one fp16 scale per 32 values, 8.5 bits/value; a static-scale
  8-bit cache would be a separate layout). It is decode-only by design: prompt
  feeding, tensor-core verify plans and batched prompt plans are disabled for
  fp8 because their kernels are q8-only.
- A `kindi kld` row for the fp8 cache is recorded at 2K and 8K on the 2B; the
  row must beat the q8_0 row (2.07–2.74e-07 nats) to be called lossless.
- Until that run exists, no support claim, catalog entry, or default profile
  uses `fp8`.

## Evidence

- `kindi/dtypes.py`: `f32_to_fp8` host reference (encode side added 2026-11-14;
  decode already present).
- `kindi/kindi.cu`: device E4M3 encode/decode and the decode store/score/value
  kernels. Host/device parity is a release gate for this row (see below); until
  then the cache remains experimental and the KLD/verify/peak numbers are the
  only claim allowed.
- `tests/test_dtypes.py`: all-pattern round-trip, named values, saturation,
  tie-to-even, and subnormal rounding.
- `tests/test_kld.py`: the fp8 variant is registered with the KLD gate.
- KLD gate, RTX 4060 Ti, 2B (`kindi kld`, teacher-forced; JSON in the gitignored
  `bench-logs/req0014-fp8-kld/kld.json`): tp-q8 2.78e-07 (2K) / 2.06e-07 (8K) nats;
  **tp-fp8 2.48e-06 (2K, 8.9x q8) / 2.80e-06 (8K, 13.6x q8)**, 100% same-top,
  PPL ratio 1.00006 / 1.00008 (k8v4: 1.30e-04 / 2.26e-04, ratio 1.00089 / 1.00109).
  Verdict: **not distribution-lossless** — it is ~10x q8_0's drift, far better than
  k8v4, but above the "no worse than q8_0" bar.
- `kindi verify` (2B, RTX 4060 Ti, `KINDI_KV=fp8 KINDI_KV_EXPERIMENTAL=1`): **3/4**
  (prompt 1 first differs at token 30; the other three are 40/40). q8_0 is 4/4.
  The fp8 cache is therefore lossy and remains experimental.
- Peak (sampled, device-wide, ctx 8192, 2B): fp8 2,856 MiB used (654 MiB over idle)
  vs q8_0 2,895 MiB (690 over idle); the ~39 MiB saving is the disabled chunk
  buffers, not the cache (same 8.5 bits/value). Prompt read is slower without
  the chunk path (200.6 vs 213.6 tok/s); decode was similar (151.7 vs 127.2 at
  position 8000 in this pair of runs; not a repeated median).
