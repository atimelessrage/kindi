# REQ-0017: Uneven tensor splits for unequal-capacity GPUs

- Status: experimental

## Requirement

A two-card tensor-parallel run must not require the two cards to share work 50/50 when their
capacities differ. For a pair such as one 6 GB card and one 8 GB card, the installer must offer
the proportional split (`KINDI_TP_SPLIT=auto`) so the engine gives the larger card the larger
aligned share of the components that can move; the smaller card must still hold its complete
per-card slice, and token results must not be assumed to be supported without a real card run.

## Acceptance

- The engine already implements a complete aligned layout via `KINDI_TP_SPLIT=auto` in
  `kindi/tp.py`: per-card GDN groups, attention query/KV heads, FFN rows and columns and
  output-head rows. The equal split remains the default when the installer does not opt in.
- The installer selects the proportional layout for a two-card setup whose cards have unequal
  memory, and fake-table tests pin both the offer for a 6 GB + 8 GB pair and the environment in
  the resulting profile.
- The installer does not claim mixed-card support: an installation offer is not a card-support
  result, and no verify, server or peak-VRAM record is implied without a real mixed-card run.

## Evidence

- `install.sh`: pair profiles set `KINDI_TP_SPLIT=auto` for unequal cards; equal-capacity pairs
  retain the historical equal layout.
- `tests/test_installer_cards.py`: fake-table coverage for a 6 GB + 8 GB pair and the selected
  proportional environment.
- No mixed-card GPU record exists in this work: the layout is implemented and installer-selected,
  but token exactness and peak VRAM remain unverified on real unequal hardware.
