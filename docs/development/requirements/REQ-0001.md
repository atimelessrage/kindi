# REQ-0001: Greedy output matches llama.cpp

- Status: active

## Requirement

With the exact head and greedy sampling, Kindi must produce the same token sequence as
llama.cpp for the same GGUF on a verified path. A first difference is acceptable only when
llama.cpp's own top-2 log-probability gap makes the token a recorded tie.

## Acceptance

- `kindi verify` passes every prompt for a supported model/device/engine combination.
- A tie is reported with the token position and the recorded gap.
- A performance path that changes the first divergent token cannot become the default
  without an explicit decision and a new verification record.

## Evidence

- [`VERIFICATION.md`](../../VERIFICATION.md) records the per-card and per-engine runs.
- `kindi/verify.py` implements the comparison; `tests/test_plan_engine.py` covers plan
  guards that protect exactness.
- The 2B, 4B and 9B plain GPU paths and the 2B tc path are token-exact; the 4B tc path is
  three exact prompts plus one accepted llama.cpp tie with the FD fallback.
