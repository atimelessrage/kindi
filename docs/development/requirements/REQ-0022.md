# REQ-0022: Hardware identification and per-machine autotuning

- Status: experimental

## Requirement

Two questions stand between a user and a working setup, and neither had a solid answer: *what can
this machine do* and *which configuration does this model actually run best with here*. The
installer answers the first crudely (a card class and a memory count), `kindi info` answers only for
the current device, and the placement settings (tandem split, tensor-parallel split, MoE decode
slots, CPU engine) were chosen by hand from measurements recorded in prose.

`kindi caps` reports what the driver and the OS say about each card and the CPU, keeping hardware
facts apart from the Kindi paths those facts enable. `kindi autotune` measures the configurations
this host can run and ranks them, so the recommendation is a measurement rather than a guess.

## Acceptance

- **A1 (done 2026-11-17): identification is layered and never guesses.** `kindi/caps.py` reads
  `nvidia-smi` (index, name, UUID, PCI bus, compute capability, total/free VRAM, driver), falls back
  to `pynvml`, then CuPy, and reports "none detected" when no source answers. A driver without a
  `compute_cap` column is reported as unknown rather than inferred from the name. CPU: the engine's
  own probe (`kindi/cpu.py`, so tier/build cannot disagree) plus model name and core counts (WMI on
  Windows, `/proc/cpuinfo` on Linux), L2/L3, AVX-512/AMX, and the CPU-engine toolchain. On Windows
  the AVX/AVX2/AVX-512F flags come from `kernel32.IsProcessorFeaturePresent` (39/40/41) — the taken
  half of the archived 2026-11-09 CPUID draft — and are merged only where the engine probe has no
  answer; FMA3/F16C have no kernel32 constant and stay unknown there with that said in the output.
  Evidence: `python -m kindi caps` on the RTX 4060 Ti + i7-8086K host reports `sm_89`, 8188 MiB
  total / 6994 MiB free, driver 617.42, PCI `00000000:01:00.0`, the hardware feature list, the
  four Kindi paths, the CPU marketing name, 6/12 threads and L3 12 MiB;
  `tests/test_caps.py` (14 tests) pins the parsers, the capability gates, the no-card answer, the
  unknown-not-guessed rule and the missing-toolchain message.
- **A2 (done 2026-11-17): the report separates "has the silicon" from "Kindi uses it".** AVX-512 is
  printed as present-but-unused; FP8 appears under Kindi paths only at sm_89+ and names
  `KINDI_G4_FP8=0`. A feature the OS does not expose is `unknown`, never `unsupported`.
- **A3 (done 2026-11-17): autotune proposes only what this host can run, and every score is
  measured.** Candidates come from the hardware report and the pack manifest: no two-card split on a
  one-card host, no Lightning decode-cache knob for a dense pack, no tandem below four physical
  cores. Each candidate is one child `kindi bench --sample-vram --json` run; a failed candidate is
  printed with the child's last line and never scored. Ranking is by decode tok/s, with a
  reduced-context run ranked below a full-context one. `--dry-run` plans without loading weights.
  Evidence: `tests/test_autotune.py` (18 tests, incl. the child-command shape, env propagation, the
  failed-run path, ranking and rendering).
- **A4 (done 2026-11-17, measured on this host):** Bonsai 2B, `--ctx 8192`, one RTX 4060 Ti:
  `gpu0` 97.4-97.8 tok/s decode / 111.7-113.0 read / 3,050 MiB sampled peak (winner);
  `tandem-auto` refused by the planner ("already fits … a split would only make it slower");
  `tandem-gdn:8` failed for a missing compiler (no clang on `PATH`), reported as such. Recorded in
  [docs/AUTOTUNE.md](../../AUTOTUNE.md).
- **A5 (open): two-card and MoE candidates are unmeasured.** This host has one card and no Lightning
  pack, so `tp-2-auto`/`tp-2-equal` and `dcache-*` are covered by unit tests only. A two-card rig run
  is the gate.
- **A6 (standing rule): no exactness claim.** Placement-changing winners must pass `kindi verify`
  before being served; the tuner prints that requirement and does not re-measure exactness itself.
