# REQ-0024: Speculation state is reported as effective, and the head is verified on load

- Status: proposed

## Requirement

A documented feature that silently degrades is worse than one that is absent: the reader has no way
to tell "on" from "requested". Two halves are required.

1. **Effective, not requested.** `/health` (and the startup log and `kindi info`) must answer what is
   actually running: which mode, whether the drafter/head loaded, and why not when it did not.
2. **Integrity on load.** The MTP head is a 60 MB downloaded weight file registered in
   `kindi/mtp_heads.json` with `sha256` and `bytes`. Loading it must check both and refuse on a
   mismatch, naming the file and the expected hash prefix.

Measured motivation: for four releases `server.py` `drafting()` answered `enabled: true, method:
mtp` from `KINDI_SPEC` alone while the head's graph never built, and the only trace was the log line
`speculation off: the MTP head … did not load (kindi: cuGraphAddKernelNode failed (1))`.
`mtp_heads.json`'s hash was used by hand, once, this round — never by the code.

## Acceptance

- **A1 (open): `/health` reports the effective state.** With `KINDI_SPEC=mtp` and a head that fails
  to load, `drafting()` answers `enabled: false` plus a `reason` string, and the mode it fell back
  to; with a head that loads it answers `enabled: true`, `head: <basename>`, and the head's
  `sha256` prefix. An app-level test builds both cases.
- **A2 (open): the metrics carry the mode they belong to.** `kindi_spec_drafted_tokens_total` and
  `kindi_spec_accepted_tokens_total` are exported with the effective mode as a label (or an
  `kindi_spec_mode_effective` gauge), so an acceptance ratio is never attributed to a mode that is
  not running.
- **A3 (open): the head is checked before its weights reach the card.** `MTPDraft` refuses a file
  whose `sha256` or size disagrees with `kindi/mtp_heads.json`, with a message naming the file, the
  expected and the found digest; a head that is not registered is refused unless
  `KINDI_MTP_HEAD_ALLOW_UNREGISTERED=1` (the local-development escape hatch), and that variable is
  documented in the regenerated configuration reference.
- **A4 (open): the startup log says which of the two happened.** One line either way, and an
  unregistered/refused head is a warning, not a debug line.
- **A5 (standing): no new speculative behavior.** This requirement adds no decoding change; the
  counters and modes it reports are the existing ones.

## Evidence

- Existing: `kindi/server.py` `drafting()` (requested-state bug), `kindi/spec.py` `_optional()`
  (one log line, no state), `kindi/mtp.py` `MTPDraft.__init__` (`np.load`, no digest),
  `kindi/mtp_heads.json` (the unused registry).
- Video of the failure: `CURRENT-VS-KINDI-0.6.md` §41 and `docs/MTP.md`; fixed head load in
  `d1d23f2`; the hash was verified by hand: `1b5c0c79…`, 60,960,552 bytes.
- Tests to write: app-level `/health` in both states; a unit test for the digest refusal with a
  truncated copy of a small fixture head (no 60 MB file in the repo).
