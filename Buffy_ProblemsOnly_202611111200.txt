## Critical

| # | Finding | Current status |
|---|---------|----------------|
| 1 | FMA3 fallback / Sandy Bridge crash | **Addressed in the current worktree; native Sandy Bridge hardware still unverified.** `kindi/cpu.py` selects five tiers at runtime, including an AVX-only scalar fallback and an AVX2/F16C no-FMA tier; forced 2B/4B/9B runs are 4/4 token-exact (2B 8.9 tok/s, 4B 3.9, 9B 2.0). The compile-time AVX baseline guard remains. Evidence: `docs/CPU-SUPPORT.md`, `bench-logs/cpu-isa-2b/`, `bench-logs/cpu-isa-4b-9b/`. |
| 2 | `rows16_avx512_vnni` incomplete | **Not a live code defect.** No such kernel or VNNI implementation exists in this tree. AVX-512/VNNI/AMX acceleration is an open feature gap, not an incomplete shipped kernel. |
| 3 | CPU ISA dispatch broken | **Addressed in the current worktree.** `kindi/cpu.py` classifies the host, selects one of five tiers, builds it with explicit flags, caches it by tier and rejects a loader mismatch; `KINDI_CPU_ISA` pins a tier. `docs/CPU-SUPPORT.md` records the forced-tier evidence. |
| 4 | Tandem CUDA doorbell kernel missing | **Addressed for the Bonsai dense path in the current worktree.** `TandemEngine` supports `cpu-first`/`gpu-first` with one hidden-state handoff per token; 2B and 9B tandem cache checks are exact in both placements. It still rejects `kindi_nanbeige` and `kindi_gemma4` manifests, so this is not a generic tandem engine. See `docs/TANDEM-RUNTIME.md`, `docs/TANDEM-STATUS.md`. |
| 5 | FP8 support missing | **Partially addressed in the current worktree.** Gemma 4 accepts E4M3/E5M2 weights, and `gemma4_fp8.cu` adds native W8A8 `mma.sync` prompt GEMM on sm_89+; decode and the fallback still dequantize FP8 weights. There is no real FP8 model run and no Blackwell hardware result, so no speed or model-support claim is made. See `docs/FP8-BF16.md`. |
| 6 | `kcpu_cpuid.c` referenced but missing | **False for this tree.** Live `kindi/cpu.py` does not import it. The only copies are in the archived WIP backup. |

## Security and safety

| # | Concern | Current status |
|---|---------|----------------|
| 58 | No bounds checking on server inputs | **False for the current server.** Request bodies are capped at 16 MiB (`KINDI_MAX_BODY_MB`), malformed JSON/shape is rejected before the engine/cache, and tests cover the 413 path. |
| 59 | Prompt injection through chat template | Application/model-level risk, not a server memory-safety bug. The server does not execute tool calls automatically. No mitigation is claimed beyond the template/tool handling. |
| 60 | No rate limiting | **Addressed 2026-11-12.** The bounded admission queue (`KINDI_QUEUE_MAX`, default 8) remains; `KINDI_RATE_LIMIT_PER_MIN` now adds an in-process fixed-window limit per source address (default 0 = off), with 429, `Retry-After`, health/metrics/model-listing exemptions, and tests. Behind a reverse proxy all clients share the proxy address. |
| 61 | API key in logs | **No evidence.** Authentication uses a constant-time comparison and log messages do not print the key. |
| 62 | No sandboxing for model loading | Open trust-boundary feature; model packs are trusted local inputs. |

## Bottom line

The original list overstated the number of live correctness bugs and understated what is already
tested. The integrated branch adds a defensive CPU-build guard, the Blackwell/5060 Ti status
correction and a clean-checkout docs-link test fix; the core engine behavior is unchanged. Tandem, FP8, AVX-512/VNNI/AMX, multi-ISA dispatch, GPU CI,
Windows CI, long-context CI and the AVX-only Sandy Bridge fallback remain open work. They should
be scheduled from `docs/ROADMAP.md` and `docs/CPU-SUPPORT.md`, not treated as regressions fixed
by this report.

> **2026-11-12 correction.** The current worktree has runtime multi-ISA dispatch including the
> AVX-only/no-FMA tiers, a Bonsai-only tandem engine, native Gemma 4 FP8 prompt kernels, Windows CI
> and a manual GPU/Blackwell lane. Still open: AVX-512/VNNI/AMX, a real FP8 model run, Blackwell
> execution, generic Nanbeige/Gemma tandem, GPU memory-leak detection, long soak/race coverage,
> installer breadth, model-loading sandboxing and native hardware for the forced ISA tiers. See
> the updated rows above and `AGENTS.md` for the evidence boundaries.
